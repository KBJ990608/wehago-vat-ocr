> 설치 없이 브라우저에서 엑셀 업로드, 이미지 OCR, 매입세액 1차 판정과 세법 RAG 챗봇 `루미`를 확인할 수 있습니다.

# WEHAGO VAT OCR

신용카드 매입전표를 정리하고 부가가치세 매입세액의 `공제`, `불공제`, `검토필요`를 1차 판정하는 웹 기반 검토 지원 시스템입니다. 반복적인 전표 정리와 명확한 거래의 초기 분류를 자동화하고, 모호한 거래는 사용자가 증빙과 법령을 확인해 최종 판단하도록 설계했습니다.

## 핵심 기능

### 엑셀 업로드 및 데이터 정리

- 병합 셀 처리, 헤더 행 탐지, 두 줄 헤더 병합
- 서로 다른 컬럼명을 표준 항목으로 매핑
- 기존 판정 결과 파일 재업로드, 예시 엑셀 다운로드와 결과 내보내기

### 이미지 OCR

- 전표 이미지를 그레이스케일·대비 보정 후 Tesseract.js로 인식
- 인식 결과가 불충분한 항목은 낮은 신뢰도의 `검토필요`로 분류

### 매입세액 1차 판정

LLM이나 머신러닝을 사용하지 않는 순수 규칙 기반 판정입니다. 위에서부터 조건을
검사하고 먼저 충족된 규칙에서 판정을 확정하며, 자동 공제와 자동 불공제의 범위를
좁게 잡고 명확하지 않은 거래는 모두 `검토필요`로 남깁니다.

판정 순서는 다음과 같습니다.

1. 사업자유형이 간이과세자·면세사업자이거나 국세청 구분이 당연불공제 → `불공제`
2. 구분이 면세이고 세액이 0원이며 비과세금액이 있는 거래 → `불공제`
3. 국세청 구분이 선택불공제 또는 불공제
   - 차변계정이 접대비·기업업무추진비이고 품명·업태·종목에 접대성 거래 내용이
     함께 확인되면 → `불공제`
   - 그 외에는 국세청이 불공제로 분류했더라도 → `검토필요`
4. 국세청 구분이 공제
   - 접대, 차량, 식대, 개인·업무무관 등 사용 목적 확인이 필요한 키워드가 있으면
     → `검토필요`
   - 구분이 과세이고 세액이 있으며 사전에 정의한 품명·차변계정 조합이 함께
     일치하면 → `공제`
   - 그 외에는 → `검토필요`
5. 국세청 구분이 없거나 알 수 없는 값이면 → `검토필요`

- 판정 입력은 국세청, 사업자유형, 구분, 품명, 차변계정, 업태, 종목, 세액,
  비과세 항목만 사용합니다.
- 국세청 구분은 `당연불공제 → 선택불공제 → 불공제 → 공제` 순서로 정규화하여
  `불공제` 안의 `공제` 문자열이 공제로 인식되지 않도록 했습니다.
- `쌀`, `꽃` 같은 품명 단어 하나로 면세거래를 확정하지 않고, 사업자유형 정보가
  없으면 거래처명이나 업종으로 간이과세자·면세사업자를 추정하지 않습니다.
- 신뢰도는 예측 확률이 아니라 어떤 규칙에서 판정이 확정되었는지를 나타내는 고정
  점수입니다.
- 신뢰도, 근거 키워드, 관련 조항과 주의사항을 함께 표시합니다.
- 셀 수정 시 재판정하고 사용자가 직접 수정한 최종 판단은 유지합니다.
- 판정 필터, 행 단위 오류 사유 기록과 결과 엑셀 내보내기를 지원합니다.

`사업자유형`은 선택적 컬럼입니다. 업로드 파일에 `사업자유형`, `사업자구분`,
`과세유형`, `공급자유형`, `공급자구분` 헤더가 있으면 자동으로 인식하고, 없으면
빈 값으로 두고 1순위 규칙을 적용하지 않습니다.

### 세법 RAG 챗봇 `루미`

- 사용자의 세법 질문을 Vercel 서버리스 API로 전달
- 질문 키워드는 확인할 법령명과 조문 번호로만 연결
- 매 질문마다 국가법령정보 API에서 해당 조문의 최신 원문과 시행일자를 조회
- 검색된 근거 범위 안에서 OpenAI 답변 생성
- 코드에 조문 내용, 시행일자, 공제·불공제 결론이나 법령 요약문을 고정하지 않음
- 매핑된 공식 조문 원문을 확인하지 못하면 공제 여부를 단정하지 않고 확인 실패 안내
- 답변을 `결론 → 근거 → 확인할 사항 → 관련 근거` 순서로 표시
- 참고한 법령·해석례·판례 제목과 일자를 함께 제공

## 사용 흐름

1. 엑셀 파일 또는 전표 이미지를 업로드합니다.
2. 컬럼 매핑, 병합 셀 처리 또는 OCR로 거래 데이터를 정리합니다.
3. 규칙 기반 판정기가 각 거래를 `공제`, `불공제`, `검토필요`로 1차 분류합니다.
4. 사용자가 판정 근거와 원본 증빙을 검토하고 필요한 항목을 수정합니다.
5. 필요한 세법 질문은 루미에게 입력해 관련 근거를 확인합니다.
6. 최종 검토 결과를 엑셀로 내보냅니다.

## 세법 변경 감지 및 Human-in-the-loop

최신 법령을 조회하고 기준 조문과의 변경을 감지하여 관련 자동 판정을 잠그며, 판정 규칙의 갱신은 전문가 승인 후 이루어지도록 설계했습니다.

- 사이트 접속 시 국가법령정보 API에서 최신 법령을 한 번 조회합니다.
- 부가가치세법 제26조·제38조·제39조와 시행령 제79조를 감시합니다.
- 프로젝트 기본 기준 또는 브라우저에 저장된 관리자 승인 기준과 현재 조문의 SHA-256 해시 및 시행일자를 비교합니다.
- 변경된 조문, 시행일자, 영향받는 규칙과 관련 거래 건수를 표시합니다.
- 변경된 조문과 관련된 거래만 자동 판정을 잠그고 `검토필요`로 전환합니다.
- 기존 규칙의 예상 판정은 법 기준 사유에 남겨 검토 근거를 보존합니다.
- 관리자가 최신 조문과 판정 규칙을 검토하고 체크박스와 `승인` 확인 문구를 입력해야 기준을 갱신할 수 있습니다.
- 프로그램은 법령 변경을 이유로 판정 규칙을 임의로 자동 수정하지 않습니다.
- API가 실패하거나 일부 조문을 찾지 못해도 엑셀·OCR과 기존 판정은 유지하고 경고만 표시합니다.
- `?simulateLawChange=1`을 붙이면 실제 API 결과를 훼손하지 않고 제39조 변경과 판정 잠금을 시연할 수 있습니다. 시뮬레이션 중 실제 기준 갱신은 비활성화됩니다.

승인 기준은 `wehago-vat-approved-law-baseline` 키로 현재 브라우저의 `localStorage`에 저장되며 다른 브라우저나 기기로 동기화되지 않습니다.

## 시스템 구조

```text
사이트 접속
   ↓
최신 법령 조회 → 기본/승인 기준 조문과 비교
   ├─ 변경 없음 → 기존 규칙 판정 유지
   └─ 변경 있음 → 관련 규칙 잠금 → 검토필요
                                      ↓
                             관리자 검토·승인
                                      ↓
                               승인 기준 갱신

브라우저
   ├─ 엑셀 파싱 / 이미지 OCR
   │       ↓
   │  규칙 기반 매입세액 1차 판정
   │       ↓
   │  근거·신뢰도 표시 → 사용자 검토 → 엑셀 출력
   │
   └─ 루미 채팅 UI → POST /rag/ask → Vercel Serverless API
                                           ├─ 국가법령정보 검색
                                           ├─ 검색 근거 구성
                                           └─ OpenAI 답변 생성
```

프런트엔드에는 OpenAI API 키가 포함되지 않습니다. 브라우저는 동일 도메인의 `/rag/ask`만 호출하고, 실제 OpenAI 요청과 비밀 키 처리는 Vercel 서버 환경에서 수행합니다.

## Human-in-the-loop 원칙

- 프로그램은 세무 신고를 자동으로 확정하지 않습니다.
- 모호하거나 신뢰도가 낮은 항목은 `검토필요`로 남깁니다.
- 사용자가 직접 수정한 판정은 법령 조회 완료나 기준 갱신 시 강제로 덮어쓰지 않습니다.
- 루미의 답변은 참고자료이며 최종 세무 판단을 대체하지 않습니다.
- 법령 변경 감지와 판정 규칙의 개정은 분리되어 있으며, 규칙 갱신에는 전문가 검토가 필요합니다.

## 보안 설계

- `OPENAI_API_KEY`는 GitHub나 브라우저 코드가 아니라 Vercel 환경변수로 관리
- OpenAI 요청은 서버리스 API에서만 수행
- 질문 길이와 IP 기준 요청 횟수 제한 적용
- 질문에 주민등록번호, 계좌번호, 실제 고객명이나 전표 원문을 입력하지 않도록 안내

## 한계와 주의사항

- 규칙 기반 판정은 거래 문맥 전체를 이해하지 못하며 세무 신고를 확정하지 않습니다.
- 입력 파일에 `사업자유형` 컬럼이 없고 국세청 칸에 `공제`, `불공제`만 있으면
  1순위(간이·면세사업자, 당연불공제)와 선택불공제 구분이 동작하지 않고, 대부분의
  거래가 3순위 또는 4순위를 거쳐 `검토필요`로 남습니다.
- OCR 정확도는 이미지 해상도, 기울기, 글자 크기와 표 구성에 영향을 받습니다.
- 법령 변경 감지는 판정 규칙을 자동 개정하지 않습니다. 기준 승인 전에 현재 규칙과 개정 법령의 일치 여부를 별도로 확인해야 합니다.
- 승인 기준은 현재 브라우저에만 저장되며 서버 또는 계정 간 동기화를 제공하지 않습니다.
- 검색된 자료가 질문의 모든 사실관계를 포함한다고 보장할 수 없습니다.
- 실제 신고 전에는 원본 증빙, 최신 법령과 세무 전문가의 검토가 필요합니다.
