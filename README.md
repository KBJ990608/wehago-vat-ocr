# WEHAGO VAT OCR

신용카드 매입전표를 정리하고 부가가치세 매입세액의 `공제`, `불공제`, `검토필요`를 1차 판정하는 웹 기반 검토 지원 시스템입니다. 반복적인 전표 정리와 명확한 거래의 초기 분류를 자동화하고, 모호한 거래는 사용자가 증빙과 법령을 확인해 최종 판단하도록 설계했습니다.

## 핵심 기능

### 엑셀 업로드 및 데이터 정리

- 병합 셀 처리, 헤더 행 탐지, 두 줄 헤더 병합
- `거래처`, `가맹점명`, `상호` 등 서로 다른 컬럼명을 표준 항목으로 매핑
- 기존 판정 결과 파일을 다시 업로드해 검토 계속 진행
- 예시 엑셀 다운로드와 최종 검토 결과 내보내기

### 이미지 OCR

- 전표 이미지를 그레이스케일·대비 보정 후 OCR 수행
- Tesseract.js로 한국어·영어 텍스트 인식
- 인식 결과가 불충분한 항목은 낮은 신뢰도의 `검토필요`로 분류

### 매입세액 1차 판정

- 면세, 불공제, 검토필요, 공제, 결제수단 키워드 사전 적용
- 국세청 공제구분과 거래 내용을 함께 고려
- 판정 결과와 함께 신뢰도, 근거 키워드, 관련 조항과 주의사항 표시
- 셀 수정 시 재판정하고, 사용자가 직접 수정한 최종 판단은 유지
- 공제·불공제·검토필요 필터와 행 단위 오류 사유 기록

### 세법 RAG 챗봇 `루미`

- 사용자의 세법 질문을 Vercel 서버리스 API로 전달
- 질문의 실무 표현을 법률 용어와 핵심 조문으로 확장해 검색
- 국가법령정보 검색·상세 조회 결과와 핵심 조문을 답변 근거로 구성
- OpenAI API가 검색된 근거 범위 안에서 답변 생성
- 답변을 `결론 → 근거 → 확인할 사항 → 관련 근거` 순서로 표시
- 참고한 법령·해석례·판례 제목과 일자를 함께 제공

예시 질문:

```text
접대비 매입세액은 공제되나요?
```

루미는 질문을 `기업업무추진비`와 연결하고, 관련 핵심 조문과 검색 자료를 근거로 결론과 추가 확인사항을 제시합니다.

## 사용 흐름

1. 엑셀 파일 또는 전표 이미지를 업로드합니다.
2. 컬럼 매핑, 병합 셀 처리 또는 OCR로 거래 데이터를 정리합니다.
3. 규칙 기반 판정기가 각 거래를 `공제`, `불공제`, `검토필요`로 1차 분류합니다.
4. 사용자가 판정 근거와 원본 증빙을 검토하고 필요한 항목을 수정합니다.
5. 필요한 세법 질문은 루미에게 입력해 관련 근거를 확인합니다.
6. 최종 검토 결과를 엑셀로 내보냅니다.

## 시스템 구조

```text
브라우저
   │
   ├─ 엑셀 파싱 / 이미지 OCR
   │       ↓
   │  규칙 기반 매입세액 1차 판정
   │       ↓
   │  근거·신뢰도 표시 → 사용자 검토 → 엑셀 출력
   │
   └─ 루미 채팅 UI
           ↓ POST /rag/ask
      Vercel Rewrite
           ↓ /api/lumi
      Vercel Serverless API
           ├─ 핵심 조문 매핑
           ├─ 국가법령정보 검색·상세 조회
           ├─ 검색 근거 구성
           └─ OpenAI 답변 생성
```

프런트엔드에는 OpenAI API 키가 포함되지 않습니다. 브라우저는 동일 도메인의 `/rag/ask`만 호출하고, 실제 OpenAI 요청과 비밀 키 처리는 Vercel 서버 환경에서 수행합니다.

## Human-in-the-loop

```text
업로드·OCR
    ↓
규칙 기반 1차 판정
    ↓
공제 / 불공제 / 검토필요
    ↓
법령·증빙 확인 및 사용자 수정
    ↓
최종 결과 내보내기
```

- 프로그램은 세무 신고를 자동으로 확정하지 않습니다.
- 모호하거나 신뢰도가 낮은 항목은 `검토필요`로 남깁니다.
- 루미의 답변은 참고자료이며 최종 세무 판단을 대체하지 않습니다.
- 사용자가 거래 목적, 공급받는 자, 증빙 형태와 최신 법령을 확인해 최종 판단합니다.

## 기술 스택

| 구분 | 기술 |
|---|---|
| 웹 UI | React 19 |
| 개발·빌드 | Vite |
| 엑셀 처리 | SheetJS (`xlsx`) |

| 아이콘 | lucide-react |
| 법령 검색 | 국가법령정보 API, Korean Law Search 프록시 |
| 생성형 AI | OpenAI API |
| 서버 API | Vercel Serverless Functions |
| 배포 | Vercel |
| 선택적 데스크톱 실행 | Electron 43, Electron Forge |

## 보안 설계

- `OPENAI_API_KEY`는 GitHub나 브라우저 코드가 아니라 Vercel 환경변수로 관리
- OpenAI 요청은 서버리스 API에서만 수행
- 질문은 800자 이내로 제한
- IP 기준 간단한 요청 횟수 제한 적용
- API 응답과 브라우저 캐시를 통한 비밀정보 노출 방지
- 질문에 주민등록번호, 계좌번호, 실제 고객명이나 전표 원문을 입력하지 않도록 안내

## 로컬 실행

```bash
git clone https://github.com/KBJ990608/wehago-vat-ocr.git
cd wehago-vat-ocr
npm install
npm run dev
```

기본 개발 주소는 `http://localhost:5173`입니다.

웹 빌드 확인:

```bash
npm run build
```

Electron 개발 실행은 선택 사항입니다.

```bash
npm run electron:dev
```

## 배포 환경변수

Vercel 프로젝트의 `Environment Variables`에 아래 값을 등록합니다.

| 변수 | 필수 여부 | 설명 |
|---|---:|---|
| `OPENAI_API_KEY` | 필수 | 루미의 OpenAI API 인증키 |
| `KSKILL_PROXY_BASE_URL` | 선택 | 법령 검색 프록시 주소. 미설정 시 기본 주소 사용 |

환경변수를 추가하거나 변경한 뒤에는 새 배포가 필요합니다. 실제 API 키는 README, 코드, GitHub 커밋 또는 브라우저용 환경변수에 넣지 않습니다.

## 한계와 주의사항

- 규칙 기반 판정은 거래 문맥 전체를 이해하지 못하며 세무 신고를 확정하지 않습니다.
- OCR 정확도는 이미지 해상도, 기울기, 글자 크기와 표 구성에 영향을 받습니다.
- 법령 검색 결과와 핵심 조문 매핑은 세법 개정에 맞춰 지속적으로 갱신해야 합니다.
- 검색된 자료가 질문의 모든 사실관계를 포함한다고 보장할 수 없습니다.
- 실제 신고 전에는 원본 증빙, 최신 법령과 세무 전문가의 검토가 필요합니다.
