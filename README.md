# WEHAGO VAT OCR

**🔗 라이브 앱:** [WEHAGO VAT OCR 실행하기](https://wehago-vat-ocr.vercel.app)

신용카드 매입전표의 부가가치세 매입세액 공제·불공제 검토를 지원하는 웹 기반
프로그램입니다.

## 1. 프로젝트 소개

WEHAGO VAT OCR은 엑셀 또는 전표 이미지에서 거래 데이터를 읽고, 규칙 기반으로
`공제`, `불공제`, `검토필요`를 1차 판정하는 검토 지원 도구입니다. 판정 결과와
함께 근거 키워드, 신뢰도, 관련 조항과 주의사항을 보여주며 사용자가 결과를 직접
수정하거나 재판정할 수 있습니다.

이 프로그램은 세무 신고를 자동으로 확정하지 않습니다. 반복적인 데이터 정리와
1차 분류를 지원하고, 최종 판단은 원본 증빙과 현행 법령을 확인한 사용자가
수행하도록 설계했습니다.

## 2. 개발 배경과 해결하려는 문제

부가가치세 신고 과정에서는 다수의 신용카드 매입전표를 반복적으로 확인해야
합니다. 회사마다 엑셀 형식과 컬럼명이 다르고, 전표 이미지의 내용을 다시
입력하거나 거래 성격과 불공제 사유를 건별로 검토하는 데 시간이 소요됩니다.

이 프로젝트는 다음 업무를 줄이는 것을 목표로 합니다.

- 서로 다른 엑셀 형식의 헤더와 거래 데이터 정리
- 전표 이미지의 텍스트 입력
- 명확한 키워드에 대한 반복적인 1차 분류
- 검토가 필요한 거래 식별
- 판정 결과와 근거의 엑셀 정리

## 3. 주요 기능

### 엑셀 업로드 및 전표 데이터 정리

- 병합 셀 채우기, 헤더 행 탐지와 두 줄 헤더 병합
- `거래처`, `가맹점명`, `상호` 등 컬럼 별칭을 표준 컬럼으로 매칭
- 기존 판정 결과 파일을 다시 올려 검토 작업 계속 진행
- 업로드 형식을 확인할 수 있는 예시 엑셀 다운로드

### 이미지 OCR

- 업로드 이미지를 그레이스케일과 대비 보정 후 OCR 수행
- Tesseract.js의 한국어·영어 인식 결과를 거래 행으로 변환
- 인식 결과가 불충분한 항목을 낮은 신뢰도의 `검토필요`로 분류

### 매입세액 1차 판정

- 면세, 불공제, 검토필요, 공제와 결제수단 키워드 사전 사용
- 국세청 공제구분과 거래 내용을 함께 고려
- 우선순위에 따라 `공제`, `불공제`, `검토필요`로 분류
- 근거 키워드, 신뢰도, 근거 조항, 주의사항과 법적 근거 표시
- 국가법령정보 검색 결과를 이용한 법령·유권해석·판례 근거 보완

### 사용자 검토와 결과 관리

- 입력 셀을 수정하면 해당 행을 규칙에 따라 재판정
- 판정 결과를 사용자가 직접 수정한 경우 사용자 판단 유지
- 공제·불공제·검토필요 필터링
- 잘못된 판정에 대한 행 단위 오류 사유 기록
- 검토 결과를 엑셀 파일로 내보내기

### 세법 RAG 챗봇 `루미`

- 화면 오른쪽 아래에서 세법 질문 입력
- 별도 `tax-ruling-rag` 서버의 검색 결과와 답변 수신
- 답변과 함께 참고한 문서 제목과 일자 표시

## 4. 실제 사용 흐름

1. 엑셀 파일 또는 전표 이미지를 업로드합니다.
2. 컬럼 매핑, 병합 셀 처리 또는 OCR을 통해 데이터를 정리합니다.
3. 규칙 기반 판정기가 각 거래를 1차 판정합니다.
4. 모호하거나 근거가 부족한 항목을 `검토필요`로 구분합니다.
5. 사용자가 원본 증빙과 법령 근거를 확인하고 결과를 수정합니다.
6. 최종 검토 결과를 엑셀로 내보냅니다.

## 5. AI·RAG 챗봇 구조

두 저장소의 역할을 분리했습니다.

| 저장소 | 역할 |
|---|---|
| `wehago-vat-ocr` | 엑셀·이미지 입력, OCR, 규칙 기반 판정, 검토 화면과 루미 채팅 UI |
| `tax-ruling-rag` | 법령·판례·행정규칙 색인, BM25 검색, 검색 근거를 포함한 답변 생성 API |

`wehago-vat-ocr`의 루미는 `/rag/ask`로 질문을 보내고, RAG 서버는 관련 문서를
검색한 뒤 상위 결과를 근거로 답변합니다. OpenAI API 키가 없는 경우
`tax-ruling-rag`는 생성형 답변 대신 검색 결과를 반환하도록 구현되어 있습니다.

챗봇 답변은 참고자료이며 최종 세무 판단을 대체하지 않습니다. 실제 거래의 목적,
증빙, 과세 여부와 최신 법령은 사용자가 별도로 확인해야 합니다.

## 6. Human-in-the-loop 구조

```text
업로드·OCR
    ↓
규칙 기반 1차 판정
    ↓
공제 / 불공제 / 검토필요
    ↓
사용자의 증빙·법령 확인 및 수정
    ↓
결과 내보내기
```

- 프로그램은 반복적인 1차 판정과 검토 대상 추출을 지원합니다.
- 모호하거나 신뢰도가 낮은 항목은 `검토필요`로 남깁니다.
- 사용자가 거래 성격과 증빙을 확인해 최종 공제 여부를 판단합니다.
- 사용자 수정 결과를 자동 판정이 다시 덮어쓰지 않도록 구분합니다.

## 7. 기술 스택

| 구분 | 기술 |

## 8. 시스템 구조

```text
브라우저 또는 Electron
┌──────────────────────────────────────────────┐
│ 엑셀 업로드 / 이미지 OCR                     │
│                ↓                             │
│ 데이터 파싱·표준화                           │
│                ↓                             │
│ 규칙 기반 매입세액 1차 판정                  │
│                ↓                             │
│ 근거·신뢰도 표시 → 사용자 검토 → 엑셀 출력   │
│                                              │
│ 루미 채팅 UI ── POST /rag/ask                │
└──────────────────────┬───────────────────────┘
                       │
                       ▼
┌──────────────────────────────────────────────┐
│ tax-ruling-rag                               │
│ 법령·판례·행정규칙 BM25 검색                 │
│ 검색 결과 조립 → OpenAI 답변 또는 검색 폴백  │
└──────────────────────────────────────────────┘
```

전표의 규칙 판정은 프런트엔드에서 수행합니다. 법령 조회와 RAG 질문은 외부
서비스로 요청되므로 민감한 고객정보나 전표 원문을 질문에 입력하지 않아야 합니다.

## 9. 로컬 실행 방법

```bash
git clone https://github.com/KBJ990608/wehago-vat-ocr.git
cd wehago-vat-ocr
npm install
npm run dev
```

기본 개발 주소는 `http://localhost:5173`입니다.

웹 빌드는 다음과 같이 확인할 수 있습니다.

```bash
npm run build
```

Electron 코드는 선택적 데스크톱 실행을 위해 유지하고 있습니다.

```bash
npm run electron:dev
```

Windows 설치본 제작은 필수 실행 경로가 아니며 필요할 때만
`npm run electron:make:win`을 사용합니다.

## 10. 환경 변수

실제 키와 비밀번호는 저장소에 커밋하지 마세요.

| 변수 | 사용 위치 | 설명 |
|---|---|---|
| `LAW_API_OC` | 웹 | 국가법령정보 공동활용 계정 |
| `KSKILL_PROXY_BASE_URL` | 웹 | 법령 검색 프록시 주소 |
| `RAG_API_BASE_URL` | Vite 개발 서버 | `/rag`가 전달될 RAG 서버 주소 |
| `APP_ENABLE_LOGIN` | 웹 빌드 | 선택적 로컬 로그인 화면 사용 여부 |
| `APP_LOGIN_EMAIL` | 웹 빌드 | 로컬 데모 로그인 계정 |
| `APP_LOGIN_PASSWORD` | 웹 빌드 | 로컬 데모 로그인 비밀번호 |
| `ELECTRON_START_URL` | Electron | 개발 서버 주소 |
| `OPENAI_API_KEY` | Electron 또는 RAG 서버 | OpenAI API 인증키 |
| `OPENAI_MODEL` | Electron 또는 RAG 서버 | 사용할 OpenAI 모델 |

프런트엔드 빌드에 포함되는 값은 브라우저에서 확인될 수 있습니다.
`APP_LOGIN_EMAIL`과 `APP_LOGIN_PASSWORD`를 실제 인증정보 보호 수단으로 사용하면
안 됩니다. 현재 로그인 기능은 기본적으로 비활성화된 로컬 데모 기능입니다.

## 11. 별도 `tax-ruling-rag` 서버 실행

```bash
git clone https://github.com/KBJ990608/tax-ruling-rag.git
cd tax-ruling-rag
pip install -r requirements.txt

# OpenAI 키는 소스가 아니라 실행 환경에 설정
set OPENAI_API_KEY=your_openai_api_key_here

python app.py --build
python api.py
```

API 서버는 기본적으로 `127.0.0.1:8765`에서 실행됩니다. 이후 다른 터미널에서
`wehago-vat-ocr`의 Vite 개발 서버를 실행하면 `/rag` 요청이 해당 서버로
전달됩니다.

## 12. 한계와 주의사항

- 규칙 기반 판정은 거래 문맥 전체를 이해하지 못하며 세무 신고를 확정하지 않습니다.
- 국세청 공제구분, 거래 목적, 세금계산서와 원본 증빙을 함께 확인해야 합니다.
- 키워드 사전과 조항 매핑은 세법 개정에 맞춰 갱신해야 합니다.
- OCR 결과는 이미지 해상도, 기울기와 표 구성에 영향을 받습니다.
- 오류 신고 내용과 선택적 로그인 정보는 브라우저 로컬 상태에 저장되며 별도
  서버 데이터베이스로 관리되지 않습니다.
- 현재 Vercel 설정에는 `/rag` Production rewrite가 없습니다. 따라서 라이브
  웹의 전표 판정 기능은 사용할 수 있지만 루미 답변을 사용하려면 공개 RAG
  API와 안전한 프록시 연결을 별도로 구성해야 합니다.
- 패키징된 Electron에서는 프런트엔드의 `/rag/ask` 경로를 중계하는 개발 서버가
  없으므로 현재 루미 RAG 채팅이 동작하지 않습니다.
- 법령·RAG 외부 요청에는 개인정보, 실제 고객명이나 전표 원문을 포함하지 않는
  것이 안전합니다.
