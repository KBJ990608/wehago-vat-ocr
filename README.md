# WEHAGO VAT OCR

신용카드 매입전표의 **부가가치세 매입세액 공제·불공제 검토를 지원하는 데스크톱 앱**이다.
엑셀이나 전표 이미지를 올리면 거래 내용을 읽어 1차 판정과 근거 조항을 제시한다.

세법 질의는 별도 저장소인 [tax-ruling-rag](https://github.com/KBJ990608/tax-ruling-rag)
서버와 연결해 챗봇 '루미'가 답한다.

Electron + React 기반이며, 판정 로직은 단말 안에서만 동작한다.

## 개발 배경

세무사무소에서 부가가치세 신고 시기마다 수백 건의 매입전표를 반복 검토하면서
같은 판단을 계속 되풀이한다는 점이 문제였다. 거래 내용을 보고, 사업 관련성을 따지고,
세법상 불공제 사유에 해당하는지 확인하는 과정이다.

건마다 판단 기준은 크게 다르지 않은데 건수가 많아 시간이 소요된다. 이 반복 판단을
자동화하고 사람은 애매한 건에 집중하도록 보조하려고 만들었다.

## 주요 기능

### 전표 입력

- **엑셀 업로드** — 병합셀 채우기, 헤더 행 자동 탐지, 두 줄 헤더 병합, 컬럼 별칭 매칭
  (`거래처`/`가맹점명`/`상호` 등을 같은 항목으로 인식)
- **이미지 OCR** — 전표 이미지를 그레이스케일·대비 보정 후 Tesseract.js 로 인식해 행으로 변환
- **결과 파일 재업로드** — 내보낸 판정 결과 파일을 다시 올려 이어서 검토

### 매입세액 판정

규칙 기반으로 1차 판정한다. 외부 통신 없이 단말에서 처리된다.

- 면세 / 불공제 / 검토필요 / 공제 / 결제수단 5개 키워드 사전으로 행을 대조
- 우선순위에 따라 `공제` · `불공제` · `검토필요` 중 하나로 판정
- 국세청 공제구분 값이 있으면 우선 반영하되, 검토가 필요한 키워드가 함께 있으면
  `검토필요`로 낮춘다
- 판정마다 근거 키워드, 신뢰도, 근거 조항, 주의사항을 함께 표시
- 국가법령정보 API로 부가가치세법 조문 원문을 조회해 근거에 덧붙임

### 검토 지원

- 표에서 셀을 수정하면 즉시 재판정
- 판정 결과 컬럼을 직접 수정하면 사용자 입력을 유지
- 판정 구분별 필터
- 행 단위 **오류 신고** — 잘못된 판정에 사유를 기록 (현재 화면 상태에만 저장되며
  앱을 종료하면 사라진다)
- 판정 결과 엑셀 내보내기, 업로드 예시 파일 내려받기

### 세법 질의 챗봇 '루미'

- 화면 우측 하단에서 열어 세법 질문을 입력
- `tax-ruling-rag` 서버가 법령·판례·행정규칙을 검색하고, 검색 결과를 근거로 답변 생성
- 답변과 함께 참고한 문서 제목·일자를 표시

### 로그인

- 환경 변수 `APP_ENABLE_LOGIN=true` 일 때만 활성화되는 **선택 기능** (기본값 비활성)
- 이메일·비밀번호 로그인과 회원가입을 제공하며, 계정 정보는 브라우저 `localStorage`에 저장
- 로그인 계정에 따른 역할 구분이나 기능 제한은 두고 있지 않다

### 보안 구조

- Electron 렌더러는 `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`
- 메인 프로세스와의 통신은 `electron/preload.cjs` 의 contextBridge 로만 연결
- API 키는 코드나 저장소에 두지 않고 사용자 환경 변수에서 읽는다
- 판정 처리 경로에는 외부 네트워크 호출이 없다

## 시스템 구조

```
┌─────────────────────────────────────────────┐
│  WEHAGO VAT OCR  (Electron + React)         │
│                                             │
│   엑셀 / 이미지 입력                          │
│        ↓                                    │
│   파싱 · OCR                                 │
│        ↓                                    │
│   규칙 기반 판정  ← 단말 내 처리, 외부 통신 없음  │
│        ↓                                    │
│   판정 결과 · 근거 조항 표시                    │
│        ↓                                    │
│   검토 · 수정 · 엑셀 내보내기                   │
│                                             │
│   챗봇 '루미'  ──┐                            │
└──────────────────┼──────────────────────────┘
                   │  세법 질문
                   ▼
┌─────────────────────────────────────────────┐
│  tax-ruling-rag  (Python, 별도 저장소)        │
│                                             │
│   법령 · 판례 · 행정규칙 검색                   │
│        ↓                                    │
│   검색 결과를 근거로 답변 생성                   │
└─────────────────────────────────────────────┘
```

**두 저장소가 함께 있어야 챗봇이 동작한다.** 이 저장소만 내려받으면 전표 판정 기능은
사용할 수 있지만 챗봇은 연결할 서버가 없다.

## 실행 방법

### 준비

```bash
git clone https://github.com/KBJ990608/wehago-vat-ocr.git
cd wehago-vat-ocr
npm install
```

### 개발 실행

```bash
npm run dev
```

Vite 개발 서버가 `http://localhost:5173` 에서 뜬다. 브라우저에서 바로 열어 확인할 수 있다.

### Electron 앱 실행

개발 서버를 켜 둔 상태에서 **다른 터미널**에 다음을 실행한다.

```bash
npm run electron:dev
```

### 빌드 · 패키징

```bash
npm run build              # 웹 빌드 (dist/)
npm run electron:make:win  # Windows 설치본 생성
```

### 챗봇을 사용하려면

챗봇은 `tax-ruling-rag` 서버에 요청을 보낸다. **앱보다 먼저 서버를 실행해야 한다.**

```bash
# 별도 터미널
git clone https://github.com/KBJ990608/tax-ruling-rag.git
cd tax-ruling-rag
pip install -r requirements.txt
python app.py --build      # 색인 생성
python api.py              # 127.0.0.1:8765
```

개발 서버가 `/rag` 요청을 `http://127.0.0.1:8765` 로 전달한다.

### 환경 변수

`.env` 파일을 만들어 설정한다. `.env.example` 을 참고하되 **비밀 키는 파일에 넣지 않는다.**

| 변수 | 설명 | 기본값 |
|---|---|---|
| `LAW_API_OC` | 국가법령정보 공동활용 계정(이메일 ID) | 없음 |
| `KSKILL_PROXY_BASE_URL` | 법령 조회 프록시 주소 | `https://k-skill-proxy.nomadamas.org` |
| `RAG_API_BASE_URL` | RAG 서버 주소 | `http://127.0.0.1:8765` |
| `APP_ENABLE_LOGIN` | 로그인 화면 사용 여부 | `false` |
| `APP_LOGIN_EMAIL` | 로그인 계정 | `admin@example.com` |
| `APP_LOGIN_PASSWORD` | 로그인 비밀번호 | `change-me` |

OpenAI 키는 `.env` 가 아니라 **사용자 환경 변수**로 설정한다.

```powershell
setx OPENAI_API_KEY "발급받은_키"
```

## 한계 및 주의사항

- **세무 신고를 자동으로 확정하는 도구가 아니다.** 반복 검토를 보조하는 1차 판정 도구이며,
  최종 세무 판단은 원본 증빙과 현행 법령을 확인한 뒤 전문가가 검토해야 한다.
- 판정은 키워드 사전에 기반하므로 **문맥을 이해하지 못한다.** 같은 단어라도 실제 거래
  성격이 다를 수 있어, `검토필요` 로 분류된 건과 신뢰도가 낮은 건은 사람이 확인해야 한다.
- **세법 개정 시 키워드 사전과 근거 조항 매핑을 갱신해야 한다.** 예를 들어 접대비는
  2024년 개정으로 법령상 명칭이 기업업무추진비로 바뀌었다.
- OCR 인식 결과는 원본 이미지 품질에 좌우된다. 인식 정확도가 낮은 행은 `검토필요` 로
  분류하고 경고를 표시한다.
- **패키징한 설치본에서는 챗봇이 동작하지 않는다.** 챗봇은 개발 서버가 중계하는 상대
  경로로 요청을 보내는데, 설치본에는 개발 서버가 없다. 현재 챗봇은 개발 모드에서만
  사용할 수 있다.
- 오류 신고 내용은 화면 상태에만 남아 앱을 종료하면 사라진다.
